# Datasets

These are the data files behind the eight case studies on my portfolio. Each folder holds the data **exactly as the analysis received it**, so anyone can rerun the work and get the same numbers.

| Folder | Project | Kind of data |
|---|---|---|
| `01-lending-credit-risk/` | 01 Digital lending credit risk in SQL, and 02 Predicting loan default | Synthetic |
| `03-mpesa-finance/` | 03 M-Pesa personal finance analytics | Synthetic |
| `04-customer-segments/` | 04 Customer segmentation for a SACCO | Synthetic |
| `05-insurance-quality/` | 05 Insurance data quality and claim frequency | Synthetic |
| `06-shop-sales/` | 06 Shop sales and ledger reconciliation | Synthetic |
| `07-kenya-public-data/` | 07 Kenya against six regional peers | Real public data |
| `08-workshop-production/` | 08 Workshop production and OEE | Synthetic |

**Synthetic** means I generated the data with code using a fixed random seed. It describes no real lender, SACCO, shop, insurer, workshop or person. I used it where real records would be confidential. Defects such as duplicates, missing IDs and bad dates were added on purpose so the cleaning steps have real problems to solve.

## 01-lending-credit-risk (synthetic, seed 2024)

A digital lender's database, used by two projects: **01 Digital lending credit risk in SQL** and **02 Predicting loan default**. Snapshot date: 31 December 2025.

| File | Rows | What it is |
|---|---:|---|
| `tables/customers.csv` | 1,000 | Borrowers: age, gender, county, occupation, monthly income, segment |
| `tables/loans.csv` | 560 | Loans across four products: principal, rate, term, credit score, status, days past due |
| `tables/repayments.csv` | 2,867 | Repayment schedule: due date, paid date, amounts |
| `tables/transactions.csv` | 20,000 | Wallet transactions, used for Project 02's 90-day activity features |
| `sql/lender.db` | | The same four tables as a SQLite database |
| `sql/credit_risk_queries.sql` | | The six SQL queries behind Project 01: data checks, loan-age bands, mature cohort, vintages with a window function, PAR30/PAR90, exposure at default |
| `sql/generate_lender_db.py` | | The code that generates the database |
| `powerbi/` | | A star schema (`fact_loans`, `dim_customer`, `dim_date`, `dim_product`), DAX measures and a build guide for a loan book dashboard |

To run the SQL: `sqlite3 sql/lender.db < sql/credit_risk_queries.sql`, or open `lender.db` in DB Browser for SQLite.

**Reading the PAR query.** At the snapshot date no Digital Loans or Salary Advances are still active. The only balances left on those products belong to defaulted loans, so their PAR shows 100%. For live portfolio risk, read PAR on SME Loans and Asset Finance.

## 03-mpesa-finance (synthetic)

A 24-month mobile-money statement (January 2024 to December 2025) in the shape of an M-Pesa statement export. It is not anyone's real account: every name, merchant, paybill, masked phone fragment and amount was generated by code with a fixed seed.

| File | Rows | What it is |
|---|---:|---|
| `raw/mpesa_statement_raw.csv` | 5,085 | The statement as exported, with injected defects (duplicates, bad dates, missing amounts) and 12 planted anomalies |
| `clean/mpesa_statement_clean.csv` | 5,045 | Parsed, deduplicated and categorised statement: the pipeline's output |
| `clean/mpesa_rejects.csv` | 15 | Rows set aside, each with its reason |

The raw file has two answer-key columns: `gen_category` (the true category) and `gen_anomaly` (1 for the 12 planted anomalies). The analysis never reads them. They are only used afterwards to score the categorisation rules (100% agreement) and the anomaly detector (12 of 12 caught, 0 false alarms).

## 04-customer-segments (synthetic, seed 7)

650 members of a SACCO or digital lender, described by how they use the service.

| File | Rows | What it is |
|---|---:|---|
| `customers_segmented.csv` | 650 | One row per member: `txns_per_month`, `avg_txn_ksh`, `avg_balance_ksh`, `loan_count`, `tenure_months`, `agent_share` (share of transactions done through an agent), `app_logins` |

The last two columns, `segment_id` and `segment`, are the **output** of the clustering: four segments named Agent-reliant, Power users, Light users and Savers. To rerun the analysis, drop them and cluster the seven behaviour columns.

## 06-shop-sales (synthetic, seed 2025)

A 12-store retail chain in Kenya: 20 products, sales for 2025, and the finance team's monthly ledger.

| File | Rows | What it is |
|---|---:|---|
| `raw/sales_2025_h1.csv` | 3,730 | Sales lines, January to June, with injected defects |
| `raw/sales_2025_h2.csv` | 4,305 | Sales lines, July to December, with injected defects |
| `raw/finance_ledger.csv` | 144 | Monthly revenue per store as booked by finance |
| `reference/products.csv` | 20 | Product list with category, unit cost and list price (Ksh) |
| `reference/stores.csv` | 12 | Store list with county, format and selling area (m²) |
| `clean/sales_clean.csv` | 7,981 | Cleaned, merged sales: the pipeline's output |

The ledger contains one planted Ksh 85,000 posting in store ST07, September 2025, which the reconciliation finds.

## 08-workshop-production (synthetic, seed 5150)

Six months of shift logs (April to September 2025) from a small metal workshop with five machines in series: saw, lathe, mill, drill and grinder.

| File | Rows | What it is |
|---|---:|---|
| `raw/shift_log.csv` | 2,367 | One row per machine per shift, as typed: misspelt machine and shift names, impossible values, duplicates |
| `clean/clean_log.csv` | 2,336 | The cleaned log, with good pieces, run minutes, cycle ratio and scrap loss (Ksh) added |
| `clean/rejected_rows.csv` | 19 | Rows set aside, each with its reason |

Two problems were planted for the analysis to find: the mill starts degrading from one week, and the grinder scraps more on the night shift.

## Reproducing the numbers

All headline figures on the portfolio come from these files. The code for each project, step by step, is in the [`notebooks/`](../notebooks/README.md) folder of this repository; each notebook reads these files directly. Longer walkthroughs are in Part 19 of my handbook, [Data Science from Zero to Advanced](https://merita-analytics-data-science.netlify.app/part-19).

Requirements: Python 3.12+, pandas, NumPy, scikit-learn, Matplotlib, Seaborn and openpyxl.
